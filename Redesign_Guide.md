# IRONYX — 2D Editorial UI Redesign Guide

## Purpose

This guide is specifically for redesigning the **existing IRONYX Workout Tracker**.

You are **not rebuilding the application**.

The current JavaScript already handles:

- workout data
- day navigation
- exercise rendering
- completion state
- progress calculations
- adding/editing exercises
- editing day names
- reset functionality
- localStorage persistence
- modals

Your job is to redesign the **visual layer** while keeping that functionality working.

The target style is:

> **Flat 2D + editorial + neo-brutalist influence + clean/premium fitness interface**

Do NOT turn IRONYX into an extreme punk, cyberpunk, grunge, neon, or cartoon neo-brutalist website.

---

# 1. Before Editing Anything

## Files

You will mainly edit:

```text
index.html
style.css
```

Do not rewrite `script.js` unless a visual change genuinely requires a small HTML/class change.

### Important JavaScript rule

The current JavaScript depends heavily on IDs and classes.

Before removing an element, search `script.js` for its:

- `id`
- `class`
- related selector

For example:

```html
<button id="resetBtn">
```

Before changing/removing it, search:

```js
resetBtn
```

in `script.js`.

If JavaScript uses the element, **keep the ID**.

You can redesign its appearance without breaking the ID.

# 3. First Change — Replace the Existing Theme

## File

`style.css`

## Find

Start at:

```css
:root {
```

Your current theme contains variables such as:

```css
--color-bg-primary
--color-bg-secondary
--color-bg-tertiary
--color-accent
--color-success
--color-danger
--shadow-sm
--shadow-md
--shadow-lg
--shadow-glow
--radius-sm
--radius-md
--radius-lg
--radius-xl
```

## Remove

Remove the old dark/cyan visual theme values.

Especially remove the visual dependency on:

- dark navy backgrounds
- cyan glow
- blue gradients
- large blurred shadows
- excessive rounded corners

Do NOT remove variables that JavaScript does not care about. These are CSS-only variables.

## Add

Create a new design system around:

```text
Background: warm off-white / cream
Primary: black
Accent: controlled red
Secondary neutral: light gray
Text: black/dark gray
```

Use CSS variables.

Example:

```css
:root {
    --color-bg: #f5f5f0;
    --color-surface: #ffffff;
    --color-black: #111111;
    --color-gray: #e7e7e2;
    --color-muted: #666666;
    --color-red: #e63946;

    --border-thick: 3px solid var(--color-black);
    --border-medium: 2px solid var(--color-black);

    --shadow-card: 5px 5px 0 var(--color-black);
    --shadow-small: 3px 3px 0 var(--color-black);

    --radius: 0px;
}
```

These are examples, not a complete stylesheet.

Choose the final values yourself.

`style.css`

```css

```

You can keep the system font stack.

The important change is **hierarchy**.

Use approximately:

```text
IRONYX        → bold/heavy
Day title     → bold
Exercise name → semibold/bold
Labels        → uppercase + medium/bold
Body          → regular
Small info    → muted
```

## Important correction to the original README

Do NOT blindly use `font-weight: 900` everywhere.

That will make IRONYX look aggressive and cheap.

Instead:

```text
400 → body
500/600 → supporting information
700 → important text
800 → major headings
900 → only selected branding/large graphic text
```

Use weight as hierarchy, not decoration.

# 14. Button Interaction

Use tactile movement.

Normal:

```text
[ BUTTON ]
      █
      █
```

Hover:

```text
[ BUTTON ]
    █
```

Pressed:

```text
[ BUTTON ]
```

Conceptual CSS:

```css
button {
    transition: transform 100ms ease,
                 box-shadow 100ms ease;
}

button:hover {
    transform: translate(2px, 2px);
}

button:active {
    transform: translate(4px, 4px);
}
```

But do not blindly apply this to every control.

Small controls can use a simpler state.
